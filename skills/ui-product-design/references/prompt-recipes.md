# 通用设计提示词与短契约

用户需要关键提示词、希望精炼上下文或执行容易遗漏时读取。适用于大小模型及 MoE；术语用于明确设计问题，不是保证激活特定专家的开关。能力足够且任务清楚时直接执行，不强制增加回合。

## 用术语引出具体决定

按本次问题选择相关的两三项即可。关键词后带对象、动作和检查，避免只写“高级、惊艳、专业”。

| 关键提示词 | 引出的设计决定 | 可观察检查 |
|---|---|---|
| 内容先行 / Content first | 先写实际标题、字段、动作与结果，再定布局 | 长中文和真实内容进入渲染，示例身份清楚 |
| 视觉层级 / Visual hierarchy | 指出用户先知道什么、接着做什么，再用位置、大小与间距表达 | 强调顺序与任务优先级一致，次要文字仍可读 |
| 邻近与分组 / Proximity, grouping | 按同一对象或一起使用的内容分组 | 窄屏重排后标签、说明和操作仍属于正确对象 |
| 构图与节奏 / Composition, rhythm | 用焦点、密度变化和题材图形组织阅读 | 展示页有主导表达，任务页保留操作效率 |
| 信息线索 / Information scent | 按钮和入口说明点击后得到什么 | 文案、目的地与实际结果一致，不新增未授权能力 |
| 渐进呈现 / Progressive disclosure | 区分现在必需、少用补充与独立阶段 | 必需条件直接可见，展开入口清楚，返回保留上下文 |
| 操作反馈 / Affordance, feedback | 表达可操作区域与正在发生的变化 | 触屏与键盘可用，反馈对应真实动作 |
| 状态与恢复 / State matrix, error recovery | 只覆盖适用状态，定位问题并保留输入 | 真空与无匹配分开，失败可恢复，成功有实际产物 |
| 语义 tokens / Semantic tokens | 复用颜色、文字、间距与状态的语义角色 | 同类状态一致，品牌与平台约束没有被随意重写 |

这些是设计词汇索引，不要求每页都出现九项，也不规定 hero、卡片数量、页面数或统一字号。

## 一份可执行短契约

用现有任务简报填写，最多保留本次相关字段；这是工作记录，不是界面内容或新审批步骤。

```text
用户与成果：谁在什么场景完成什么，怎样看见完成。
必须保留：品牌、平台、范围、真实行为与数据/权限约束。
内容与布局：先看什么；哪些内容一起使用；窄屏关系如何保持。
动作与状态：入口 → 动作 → 真实结果；适用失败怎样恢复。
交付与验证：实际文件或稿件；运行检查；证据与缺口。
```

例如“成员管理页”可以以身份、角色、状态与行内操作为阅读结构，创建后用实际列表结果确认；“活动展示页”可以围绕题材图形组织，但时间、地点、资格和报名入口须容易发现。同一契约可以产生不同页面形态。

## 可直接使用的通用提示

替换方括号内容，不携带无关模板。精准小修改仍走 Skill 的轻量分支。

```text
使用 $ui-product-design 完成 [产品/页面]，目标用户是 [用户]，主要成果是 [可见结果]。
平台与交付范围：[平台；实现/仅设计/改版]。
必须保留：[品牌、现有行为、内容来源和边界]。

先用短契约明确阅读顺序、内容归属、主动作、真实结果与必要状态。
选取与本任务相关的视觉层级、分组、构图节奏或错误恢复，写成具体决定。
自由设计时简短比较不同构图，选定后落实；已有准确参考时直接深化。
按契约完成授权交付，验证当前路径及受影响状态，报告真实证据和缺口。
```

## 需要分步时如何交接

上下文有限、任务多或同一次生成反复遗漏时，按“契约 → 方向 → 实现 → 验证”缩小单次关注点。每阶段交出可供下一阶段使用的决定；同一 agent 可以在同一轮顺序推进，不自动创建多名代理，不把规划当最终交付。

| 当前阶段 | 追加的短指令 | 本阶段交付 |
|---|---|---|
| 契约 | 列出范围内主要任务、真实成果、前置条件与恢复；把关键歧义留给澄清 | 精简任务清单与约束 |
| 方向 | 基于实际内容说明焦点、归属、构图、字体/色彩角色和题材表达 | 选定方向及具体布局决定 |
| 实现 | 按当前契约完成切片，再覆盖语义不同的任务；保留既有路由与行为 | 实际文件及可达状态 |
| 验证 | 从真实入口完成动作，检查成果与恢复，再看宽窄屏关系 | 检查结果、证据、缺口 |

交接只保留：已选决定、不可改变的约束、文件/路由、未解决问题、下一项检查。依据任务复杂度选择拆分粒度，不为一句按钮文案走四个阶段。

## 少量示例与模型边界

需要固定输出或模型误解任务时，给一个与当前任务相关的完整示例，如“入口名称 → 目的地 → 成功证据 → 恢复方式”，再让它迁移结构到本产品。示例说明关系，不复制品牌、业务假设或外观；不一次塞入全部参考文献。

通用提示只要求简短决定与可验证产物，不要求暴露完整思考链。思考开关、采样参数和聊天模板由实际模型及运行环境处理，不把某个供应商的特殊标签混入通用提示词。

方法来自 UX 一手资料、模型作者的提示建议和任务分解研究的综合判断，实际效果需要任务验证。来源见 [来源与取舍](sources.md)，没有跨全部模型或 MoE 路由的效果保证。
