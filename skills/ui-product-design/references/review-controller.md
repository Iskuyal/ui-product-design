# 评审控制流程

此文件供主 agent 执行，**不发送给视觉评审 agent**。评审 agent 只接收 [固定评审提示](critic-prompt.md) 和下面定义的当前证据包。

## 独立输入

新上下文的评审 agent 不继承聊天历史。提供当前入口、任务页、结果/适用状态、窄屏截图；多任务交付覆盖本次新增/显著改版的主要页面类型。最小事实简报包括：目标用户与使用场景、产品用途、用户任务、平台、页面顺序、交付模式与本次范围、明确品牌约束、用户要求保留或禁止的事项、影响可见设计的既有能力限制。只放会影响判断的事实；例如老年用户的大字号需求、必须保留的表格字段和未接后端的静态原型身份。静态方案标为静态，不伪造运行证据。

滚动叙事、空间拖动或页面过渡对任务/视觉身份有实质影响时，证据包另附同版本、同场景的短录屏与中性触发说明，包含关键过渡、快速反向/中断及适用的减少动态分支。普通轻量控件反馈无需自动扩大成视频评审。动态媒体同样记录内容哈希；录屏不能证明帧率、性能或其他设备表现。

评审环境不能读取动态证据时，明确该部分未独立评审；关键帧可支持局部状态比较，不能代替时序、节奏和连续性判断。静态评分只覆盖静态部分，不据此宣称核心动态表达达到整体精修目标。

保存或传递证据前按 [验证证据](verification.md) 处理数据，检查全部截图、动态媒体和简报中没有原始个人信息、凭据或内部敏感字段；替代内容保持代表性并标明身份。

不提供代码、作者解释、种子、修改投入、旧评分、旧批评、目标分数和“请通过”等暗示。已经选定的方向由截图体现；品牌约束可以给出，作者对方向的辩护不能给出。参考作品只有用户提供/授权且确有比较用途时才加入，保持各轮不变并说明其参考身份。

每个证据包绑定一个产物版本 ID 与截图清单。干净且包含本次所有资源的 Git 提交可用提交 ID；未提交或含未跟踪资源时，使用覆盖本次源文件及相关资源的内容指纹，可附不可复用的轮次 ID。不能只用“提交 SHA + dirty”区分不同内容。清单记录文件范围、截图内容哈希、页面、状态、视口和数据场景；排除凭据，不把内容指纹变成敏感数据副本。

这个无评分含义的 ID 随证据提供给评审，回传结果与同一 ID 关联。交付前核对当前内容指纹及截图清单未在评审后变化；影响评分的变更需重新捕获并评审。不能把不同版本、不同场景的反馈拼成一次验收。

使用 `critic-prompt.md` 的原文，每轮保持不变，仅替换独立证据包。上下文隔离靠工具的全新 agent/context 实现，不能用“忘记之前消息”冒充。环境没有此能力时，报告独立评审不可用；可以继续已授权的设计与验证，但不能宣称独立验收完成。

## 修改与完成

开始评审前，由主 agent 记录本次完成约定、评审人数、固定提示的版本/哈希及已有模型配置（无须改变继承模型）。保持各轮口径和评审规模，最终验收版本补足原定数量的全新上下文意见。确需变更时记录理由与证据影响，不能因评分不利减少人数或更换配置；不能混用不同配置的分数宣称趋势或达标。评分目标不进入评审输入：

- **普通设计/改版**：完成授权范围内的任务与适用检查，解决硬问题和重要评审缺陷；对未采用的重要建议，保存基于任务或约束的具体理由。评分作为意见报告，不单独决定完成，也不为低影响偏好反复重做。
- **高标准精修**：用户明确要求高分迭代或项目已约定时，启用分数目标。用户要求“达到9分才能完成”则保留 **≥9/10** 的独立评分门槛，同时完成普通模式的检查；其他明确目标按用户要求执行。不能因任务已经可用就宣称分数目标已达成。

仅设计时检查可见设计的问题，不能要求尚未授权的完整开发才结束，也不能把静态评分扩展成运行验收。主 agent 不把文献中的分数示例自动推广成所有任务的默认验收。

先修复高影响的三类以内问题，然后重新捕获同一页面和场景，再交给新评审上下文。保存原始反馈；记录“问题 → 改动 → 复查证据”。评分没有变化时寻找实际差距，而不是换模型、删掉不利截图或反复抽取更高分。

先检查评分有效性：原定页面类型、关键状态、适用窄屏和必要动态范围应可供评审判断；确实不适用的项目按任务排除并记录理由。关键证据无法读取或缺失时，“整体无法判断”及“局部暂评分”都不能计入完整分数目标，功能检查通过也不能补作独立视觉证据。补齐同版本证据后重新评审；不通过排除不利页面缩小已约定范围。

如使用多个评审，保留各自评分、问题与分歧；普通模式依据问题和任务证据决定，不让单一低分自动否决。已启用分数门槛时，在原定数量的评审都完成约定覆盖且总体评分有效后，以**同一当前版本**各评审的最低独立总体评分判断该目标，防止挑高分；历史分数只归档，不纳入当前门槛。影响评审的修改后，旧版本评分失效，需要该版本的新评审；不能混用不同版本的高分。任何模式都不能平均掉严重缺陷。审美分歧由主 agent 按任务证据解释，高优先级功能问题要通过实际检查解决。

默认先做最多三轮“评审 → 修订”，范围小且没有重要缺陷时一轮即可。符合本次完成约定则交付；预算耗尽、证据不可获得或连续两轮没有实质进展时，保存现有成果并明确报告未达到的约定、当前缺口及下一步。**停止不等于完成**；不能伪造通过、无限消耗或自行降低已约定的门槛。用户授权更多轮时继续，保持原评审提示。

评分是一个审美判断信号，不是客观测量或真实用户验证。最终报告同时给出独立评分、实际检查、证据范围和缺口。
