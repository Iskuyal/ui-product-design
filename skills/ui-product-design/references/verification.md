# 验证证据

在实现或原型进入交付前读取。按改动范围验证，不要求每次小修改重跑完整产品验收。

## 验证前确定环境

记录测试环境、账号/数据来源和最终动作的后果，优先使用项目已有测试环境、测试数据或明确标识的演示路径。支付、发送通知、取消预约、删除记录等真实副作用，不能因“走通 UI”就视为已获授权；已有明确授权按其范围继续，不重复询问。没有安全且授权的验证路径时，验证到副作用边界并保留证据缺口，区分模拟结果与真实业务结果。

## 证据中的数据

截图和简报优先使用授权的测试数据。必须使用真实基线时，在保存、传递和交付前去除个人信息、凭据和内部敏感字段；使用标明身份的替代内容，保持有代表性的字长、密度与状态，避免脱敏改变待评审的布局。必要事实用概括说明，不把原始敏感值放入评审上下文。各轮沿用同一处理规则，检查最终截图清单与简报，而不只检查页面上的一个字段。

## 改版基线与影响面

修改前保存本次问题的实际截图/状态、应保留的关键行为，以及将修改的共享组件或 tokens 的主要使用处。没有运行条件时记录当前可取得的静态基线与缺口。修改后用相同内容和场景复查，并抽查实际受影响的页面；例如共享输入框变化应同时检查使用它的搜索、登录和编辑表单，而非只看新搜索页。不因一个共享变量改动要求全站重新验收。

## 一条任务，多种证据

| 检查 | 操作 | 可以证明什么 |
|---|---|---|
| 页面与状态 | 实际渲染入口、任务页、结果和适用错误分支 | 当前环境的可见效果 |
| 核心路径 | 点击 CTA、完成输入、查看结果、返回；必要时刷新或深链进入 | 本次环境的交互与路由 |
| 恢复 | 模拟慢响应、失败、取消、离线等实际分支 | 模拟条件下输入保留与恢复行为 |
| 响应式 | 宽/窄视口、长内容、实际放大与重排 | 测试尺寸和内容范围的布局 |
| 辅助功能 | 键盘、可见焦点、语义名称、读屏和减少动态效果 | 已实际检查的路径；扫描器仅作补充 |
| 资源与运行 | 正常构建、控制台/运行日志、字体/图片失败降级 | 当前构建与资源状态 |
| 平台验收 | 对应客户端、模拟器或真机上的同一任务 | 该客户端/设备的证据，不能跨设备泛化 |

可访问性要求查 [平台适配](platforms.md)；表中的部分检查通过不等于完整 WCAG 符合性审计。只设计未实现时，用标注状态的稿件审查层级和任务意图，明确没有运行证据。

多任务交付对照体验契约的清单逐项记录成果、必要分支和证据。相同列表结构可以合理抽样，但导航、权限或提交语义不同的任务必须分别检查；未验收的任务保持缺口。评审截图覆盖本次新增或显著改版的主要页面类型，不用单一漂亮入口代替全部范围。

## 硬问题先修复

主动作无效、输入丢失、返回困住用户、关键文案不可读、焦点无法到达、界面与实际成果不一致，均不能被高审美分掩盖。适用的硬问题未解决时保留未完成状态。跨端共用代码不等于所有端验证通过。

长任务要有状态观察和合理退出/恢复路径。不能因为请求不可取消，就无限期封锁关闭、Escape 或返回；只有确实撤销任务时才称“取消”。按业务风险保护提交，但不把用户困住。

复用项目已有 lint/typecheck/build 和相关测试；针对确实修改的复杂交互、状态或确认缺陷补充有意义的验证。低风险样式修改用渲染与关键路径检查即可，不写只复述 CSS 实现的测试。

## 性能按项目实测

先识别目标设备/网络和项目预算。没有预算时，提出可观察检查：首个可用任务何时出现、装饰是否导致卡顿、慢网下能否操作、资源失败是否保留关键信息。需要指标时记录工具、设备、网络条件、采样与前后结果；实验室数据与真实用户数据分开报告。

不要承诺未测量的帧率、转化率或“性能优秀”。复杂视觉可通过减少首屏资源、暂停不可见动画、静态降级或移除无用效果控制成本；结果以复测为准。

## 证据记录格式

```text
版本/修改范围：
环境、平台、设备或视口：
任务与测试内容：
实际结果：
截图/操作记录/日志路径：
未验证项及原因：
```

截图使用真实渲染，标明页面/状态/视口；按阅读顺序保存，入口和目标页使用一致数据。错误状态通过实际触发或明确标识的状态演示，不篡改截图装成真实失败恢复。核心动态表达按评审控制流程提供同版本的短录屏和触发说明；静态关键帧不证明运动节奏，录屏不证明目标设备性能。
