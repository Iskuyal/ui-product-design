# 验证范围

## 可复现的仓库校验

在仓库根目录运行：

```sh
python -X utf8 -m pip install -r requirements-dev.txt
python -X utf8 scripts/validate.py
```

依赖为 Python 3.10+、PyYAML 与已有的 PowerShell。报告位于 `build/validation.json`，包含当前安装包的文件哈希；生成报告不提交。

检查包括 UTF-8、Skill YAML、展示/调用配置、仓库 Markdown 本地链接、根目录与安装包许可一致性，以及随机脚本的32/128/512长度、字符集、样本差异和31/513越界拒绝。

[GitHub Actions](../.github/workflows/validate.yml) 在 Windows 和 Linux 执行相同脚本。它验证文件与辅助脚本，不评价页面审美，也不运行原生 App 或微信小程序。

## 开发阶段的历史试用

以下试用记录日期为2026-10-02。原始产物未随公开仓库发布，因此属于结果摘要，不是读者可直接复跑的完整验收用例。

| 试用 | 实际观察 | 边界 |
|---|---|---|
| 小程序设计片段 | 23/23隔离检查通过；发现并补齐示例输入的tabBar页面声明；覆盖分享直达、回访、空状态与恢复 | Node替身和静态检查，不证明开发者工具或真机运行 |
| 后台仅设计 | 订单、权限、导出分别形成路径、状态与验证计划，没有扩大为营销页 | 文档试用，未实现后台 |
| Web语义小改 | 错字与辅助名称同步修正；与真实动作不一致的订阅改名被识别；宽窄屏与假事件检查通过 | 本地Chromium与假事件，无真实账户或订阅 |

历史评分与试用不是对任何新页面的质量承诺。没有取得真人可用性研究、真实产品跨端验收或核心动效的实际独立视觉评分。

## 验证 Skill 的实际效果

用 [网页测试提示词](../examples/web-test-prompt.md) 在独立项目中执行，观察是否完成整条任务、保留必要状态、正确缩小范围，以及是否根据实际证据修订。需要更强证据时补真实目标用户和对应客户端检查。

每次报告环境、任务、结果、证据位置与未验证项。截图、模拟器、单台设备和用户研究分别说明；不要用仓库CI或Skill评分替代产品验收。
