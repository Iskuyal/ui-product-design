# UI/UX 一手资料对通用设计提示词的启示

核查日期：2026-10-07。目的：优化中文 `ui-product-design` Skill 的可执行性，适用于大小模型，不限定 MoE；本次以完整、合理、效果不错为目标，不追逐 9 分。

## 范围与证据边界

使用 `research` 与 Exa Search Skill，通过 Exa MCP 执行 3 个搜索角度，每次请求 10 条，实际返回 30 条候选，按原始 URL 去重后仍为 30 条；读取其中 8 个一手页面。8 页均获得正文；首次抓取中 3 页受字符上限截断，随后对 2 个 GOV.UK 错误组件页扩大上限重读，W3C 页的关键说明完整可见、术语尾部仍截断。共 3 次搜索、10 次页面提取（8 个唯一 URL），没有访问付费正文、安装工具或调用生成模型。

本地差距识别只读取 `skills/ui-product-design/SKILL.md`、`references/creative-direction.md` 和 `references/experience-contract.md`。当前 Skill 已有任务路径、内容先行、真实状态、窄屏验证、语义 tokens 与反模板原则。建议补充少量判断和检查方式，融入这些已有步骤；不增加每个页面都要填的新文档或强制外观。

下表中的“可执行改进”及短契约是**从 UX 资料到 agent 工作方式的推论**，不是论文验证过的 LLM 提示效果。来源描述人的感知、任务行为、组件经验和可访问性要求；它们不能证明某些关键词提升大小模型表现，更不能证明短语会激活 MoE 特定专家。

## 可供 Skill 吸收的短契约

这是工作记录格式的建议，不是产品页面模板。小改动只记录被影响的判断，已有项目约束和准确参考优先。

```text
任务与可见成果：谁在什么场景完成什么，如何知道完成。
内容顺序：当前决定必需的信息 → 操作 → 支持信息；分组依据是什么。
布局理由：哪些内容需比较/一起使用，窄屏如何保留这些关系。
动作与反馈：入口、真实结果、下一步；少用内容是否需要展开。
适用状态：仅列本次存在的分支及恢复方式，保留哪些输入/上下文。
验证：实际渲染与交互检查，已有证据和未验证事项。
```

**成员管理页**：成果是新成员出现在真实列表。列表先给身份、角色和状态，新增/筛选靠近相应任务；同一行的修改操作属于该成员。邀请表单直接解释权限和必填字段；罕用权限术语可展开。保存失败保留输入；成功核对名单；窄屏验证身份、角色与操作不会串组。无需加宣传式 hero 或额外记忆点。

**活动展示页**：成果是读懂活动条件并进入真实报名。先给主题、时间、地点、资格与报名入口，再用真实内容组织议程和主讲者。能决定是否报名的信息直接可见，少数读者需要的交通补充可展开；题材构图可自由选择，不规定必须左右分栏或几张卡。验证 CTA 终点、窄屏信息关系与报名失败的恢复。

这些说明能使任务更可审阅；是否改善小模型执行仍需在同一任务、同一输入和真实渲染下比较。此次没有模型对比实验或 UX 受试者测试，不报告效率、成功率或转化提升。

## 取舍与后续验证

优先把“信息先后、分组关系、需要时展开、具体恢复”各补成一句判断和一个可观察检查，避免叠加长期清单。将判断放到内容/任务相关步骤，保留成熟控件、品牌参考、独特视觉与高密度工具页的选择空间。

上述 UI 结论来自资料研究与文本差距识别，不是模型对比结果。若要验证提示词效果，应保留同一批多种任务与真实内容、同样工具条件，比较改前/改后的任务覆盖、状态恢复、布局关系和实际截图；保留失败、不改期望来制造提升，不设未经用户要求的 9 分通关线。

## 实际采用的改进

1. 在原任务/内容步骤补信息顺序与窄屏归属；在方向契约补容器的分组理由；在状态说明补错误类别与定位。
2. 新增按需读取的 `references/prompt-recipes.md`，把9组中英设计词汇对应到决定和检查，允许只选相关几项，不固定页面外观。
3. 给通用短提示、5项可执行契约和可选阶段交接；复用已有简报，不增加独立文档或自动派四名代理，不因分步停在规划。
4. 关键词不作为MoE专家开关，大小模型均可采用；不强制完整思考链、不改运行时参数。

后续 Luna 试用用于核对新版指令能否产生实际产物、控制范围与报告证据。它不是MoE硬件路由测试，也不是严谨的同模型改前/改后A/B实验。具体结果应以验证记录为准，不预填通过、提升比例或审美分。
