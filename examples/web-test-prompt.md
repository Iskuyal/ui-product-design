# 网页测试提示词

复制以下正文，在独立 Web 项目中使用。若当前目录是 Skill 仓库，将演示应用放在 `demo/xiangwai-web`，不要修改 Skill 源文件。

---

使用 $ui-product-design，为“巷外”设计并实现一个可以实际操作的响应式 Web App。请在独立测试目录开发；若当前目录是 Skill 仓库，将应用放在 `demo/xiangwai-web`，保留现有 Skill 和文档。

“巷外”帮助城市年轻人安排半天的周末漫游：从路线中找到喜欢的体验，查看行程，创建自己的计划。目标用户希望快速做选择，同时享受有画面感的浏览体验。

请从着陆页进入后续功能页面，完成以下体验：

1. 着陆页：让首次访客理解用途并看见具体路线或行程预览；主按钮“找一条路线”进入探索页，回访用户能直接进入已有计划。
2. 探索页：提供至少8条虚构城市“澄湾”的示例路线，内容包含河岸、书店、咖啡、旧街和绿地等不同体验。支持兴趣和时长筛选；点击路线进入详情。无结果时可以清空条件恢复。
3. 路线详情：呈现主题、预计时长、三至四个停留点及行程顺序。用户选择出发日期和时间后创建计划；无效或缺失输入有明确提示。无效路线链接有可恢复出口。
4. 我的计划：展示实际创建的计划与时间安排，支持移除或撤销；未创建时有明确入口。刷新后保留计划，返回探索页保留筛选意图。数据保存失败时保留当前选择并给出恢复方式。

这些路线和地点都是演示内容，请清楚标识；不接地图、支付、登录或真实预约，不编造评价、用户数及实际旅行保证。数据可以本地保存，操作必须产生可见结果，不能只弹“成功”而不更新页面。

视觉上希望有鲜明的题材表达，每个模块像同一世界里的不同场景，内容组织有节奏。配色、字体、构图和图形由你判断，可以尝试像素艺术、插画或其他合适方向。请简短比较两种真正不同的方向后选一种落实；不要把方案做成只有颜色不同的通用模板。若使用随机种子，按 Skill 用 shell 生成并保持在界面之外。

中文阅读与操作优先：图形不能承载唯一业务信息，重要按钮易发现；桌面与手机都可完成任务，触屏不依赖悬停，键盘焦点清楚，尊重减少动态效果。以内容需要决定卡片、圆角和动效，不按风格黑名单判断。

已有项目沿用当前技术栈；空项目采用 React + TypeScript + Vite。先完成着陆页→探索→详情→计划的纵向切片，再完善必要状态。遇到会改变核心任务的歧义才询问，可逆细节明确假设后继续。

请实际运行并检查主按钮跳转、筛选恢复、创建计划、刷新保留、移除/撤销、无效输入、窄屏和键盘操作。保存当前入口、任务与结果的宽窄屏截图；确认路由直接访问和浏览器返回可用。

最后在工具允许时用独立子 agent 做一轮评审，依据真实截图与最小事实简报修正影响最大的几个问题；没有独立评审能力就说明缺口。不要为了分数反复推翻设计，重点是完整、合理、有辨识度且能顺畅使用。

交付可运行项目、启动命令、简短设计理由和实际验证结果。不要只交计划、静态封面或一堆无法使用的按钮；不发布到外网，不修改 Skill 本身。
